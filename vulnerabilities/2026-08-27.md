# August 27, 2026 - The Auth request page dispatched transaction fields its review never showed

|                          |                |
| -----------------------: | :------------- |
|             **Reported** | August-24-2026 |
|           **Mitigation** | August-25-2026 |
|   **Solution Completed** | August-27-2026 |

## Description

- Clients hand wallet requests to `decentraland.org/auth` through auth-server. The request page shows the user what they are about to sign, simulates the transaction, and after **Allow** dispatches it to the connected wallet.
- For `eth_sendTransaction` the simulation was built from `to`, `data` and `value`, while the dispatch forwarded the original params object. Email and social wallets run on Thirdweb, whose SDK keeps a non-standard `extraCallData` field and signs `concat(data, extraCallData)`. With an empty `data`, the field the review never looked at became the whole calldata: the page said "This transaction doesn't move any of your assets" and the wallet executed a token transfer.
- After the first fix the same shape was shown with the fee fields. A request carrying an enormous `maxFeePerGas` executed a plain 21000-gas transfer that spent most of the account's native balance on fees, while the review showed a normal fee.
- Only Thirdweb wallets were affected; browser wallets drop fields they do not know. The victim had to open a request created by the attacker's own page and click **Allow** within the request's 300-second lifetime. The path is not reachable from the official client.

### Root cause

The transaction existed twice, once as reviewed and once as dispatched, and only the first was constrained. Every field the review did not model still reached the wallet unchanged.

## Severity

Websites & Applications - Critical.

This matched "performing malicious interactions with an already-connected wallet such as modifying transaction arguments or parameters". It sat at the lower end of the tier because exploitation depends on the victim opening an attacker link and approving, and only email and social wallets are exposed.

## Solution

The page now dispatches exactly what it reviewed.

- [Auth 5.0.2](https://github.com/decentraland/auth/pull/461) (August 25) rejected any `eth_sendTransaction` field outside the standard set before signing, read calldata only from `data`, and stopped showing a simulation for such requests.
- [Auth 5.0.3](https://github.com/decentraland/auth/pull/462) (August 27) replaced that allowlist: the params are rebuilt from `to`, `data` and `value` only, and the connected wallet fills gas, fees and nonce. This closes the fee-field variant and any other field the review does not show.

The signing branch of the same page had the same shape and is covered in [2026-09-02-2](2026-09-02-2.md).
