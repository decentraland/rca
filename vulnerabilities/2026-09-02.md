# September 2, 2026 - Rental listing cancellation ignored which signer bumped the asset index

|                          |                   |
| -----------------------: | :---------------- |
|             **Reported** | August-31-2026    |
|           **Mitigation** | September-02-2026 |
|   **Solution Completed** | September-02-2026 |

## Description

- The Rentals contract invalidates signed listings through three indexes: one for the whole contract, one per signer, and one per asset. The per-asset index is also per signer, `assetIndex[contract][tokenId][signer]`: `bumpAssetIndex` increments only the caller's entry and `acceptListing` checks the lessor's.
- signatures-server keeps the off-chain copy of listings that the marketplace shows and cancels them when the rentals subgraph reports an index bump. The subgraph event carries the signer, but the server's query did not request it, and the cancellation for asset bumps matched open listings by contract, token id and nonce only.
- Any wallet could call `bumpAssetIndex` for any LAND or Estate, about 55k gas, and the next run of the cancellation job, which runs every five minutes, marked the real owner's open listing as cancelled. The listing disappeared from the marketplace until the owner published it again.
- The effect was off-chain and recoverable. The owner's signed listing stayed valid on the contract, the owner's own index was untouched, and re-listing costs a new signature and no gas. Rentals exist only on Ethereum for LAND and Estates, around eighty open listings at the time. The contract-wide and per-signer branches of the same job were already scoped correctly.

### Root cause

The off-chain mirror dropped one dimension of the on-chain key. The contract scopes the asset index to (contract, token id, signer); the cancellation query used (contract, token id), so a bump by one signer invalidated the listings of every signer of that asset.

## Severity

Websites & Applications - Critical.

This matched "taking state-modifying authenticated actions on behalf of other users without any interaction by that user". It was paid at the low end of the tier: no funds or assets were at risk, no signature was forged, and the owner recovers by re-listing.

## Solution

[signatures-server 1.10.3](https://github.com/decentraland/signatures-server/pull/491) (September 2) requests `signer` from the subgraph for asset index events and only cancels listings whose lessor is that signer, the same scoping the per-signer branch already had. An integration test covers a bump from a different signer leaving the owner's listing open.
