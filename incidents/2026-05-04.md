## What happened?

Following the resolution of [DCL-2278](https://github.com/decentraland/rca/blob/main/incidents/2026-04-17.md), in which Creator Hub–specific components in `main.crdt` caused heap corruption in the explorer, intermittent crashing in Genesis Plaza resurfaced for Windows users. The previous fix (ignoring Creator Hub components) resolved one source of corruption, but a separate underlying issue in the V8 JavaScript engine remained. Approximately 5% of our user base was affected, experiencing application closures without crash logs or dumps while moving around the plaza.

## Why did it happen?

The root cause was a memory corruption bug inside ClearScript's V8 engine binding layer, triggered by a heavy synchronous allocation burst during scene initialization (`onStart`). Genesis Plaza creates approximately 1,500 entities synchronously on startup, producing a 273 KB CRDT delta on the first frame. This volume of synchronous allocation corrupted V8 internal state (likely in the hidden-class graph, inline-cache, or object-shape transitions), which then surfaced as an `AccessViolationException` in `V8Object_Invoke` when the first `onUpdate` tick executed.

The crash was non-deterministic — different runs against the same binary died at different points in the update pipeline — which is consistent with memory corruption set up during initialization and triggered wherever V8 next dereferences the affected memory region.

During the investigation of DCL-2278, the heap corruption from Creator Hub components masked this deeper issue. Once that was resolved, the V8-level corruption became the sole remaining crash source. The issue was [escalated to the ClearScript maintainers](https://github.com/ClearFoundry/ClearScript/issues/716) with a full reproducer. They confirmed the bug and shipped a fix in ClearScript 7.5.1.

For full technical detail on the reproduction, hypothesis testing, and V8-level diagnostics, see [ClearScript issue #716](https://github.com/ClearFoundry/ClearScript/issues/716).

## Impact

- **Severity**: SEV-3
- **Users affected**: ~5% of the user base (Windows clients).
- **Symptom**: Intermittent application crashes (silent closures, no crash logs) while moving around Genesis Plaza. Frequency varied per user and was non-deterministic.
- **Duration**: 9 days from report to deployed fix.

## Solution

Upgraded to [ClearScript 7.5.1](https://github.com/ClearFoundry/ClearScript/releases/tag/7.5.1), which contains the upstream fix for the V8 memory corruption triggered by heavy synchronous allocation bursts.

## Preventive Actions

QA now includes manual stability testing of Genesis Plaza as part of each plaza deployment, covering movement through high-entity-density areas on Windows clients to catch crash regressions before they reach users.
