# July 7, 2026 - Remote users disappear when teleporting back to Genesis Plaza from a World

|                          |               |
| -----------------------: | :------------ |
| **Reported on Slack**    | July 7, 2026  |
|           **Mitigation** | July 10, 2026 |
|   **Solution Completed** | July 10, 2026 |

## What happened?

On July 7, 2026 at 21:50 (UTC), a SEV-2 crash was opened after users reported not
seeing other users when teleporting back to Genesis Plaza from a World. The next
release contained a fix for a related issue and, since the team could no longer
reproduce the problem in the release build, the crash was closed as fixed.

On July 8, 2026 the team was able to reproduce the issue after the release, so the
crash was reopened. 100% reproduction steps were found using a faulty World, and the
issue was initially (and mistakenly) attributed to that specific World.

On July 10, 2026 the actual root cause was identified and a proper solution was
deployed as a hotfix (v.0156.0).

## Why did it happen?

A fix ([unity-explorer#9041](https://github.com/decentraland/unity-explorer/pull/9041))
had been deployed to mitigate a Pulse-related issue
([unity-explorer#8827](https://github.com/decentraland/unity-explorer/issues/8827)).
That fix surfaced another Pulse issue that caused remote users to be removed from a
scene when coming back to Genesis Plaza from a World.

The root cause is a combination of **Pulse** and the **messages draining system**:

- When traveling from Genesis Plaza to a World, Pulse switches the area of interest
  almost instantly, which triggers a removal of the users in the scene. This happens
  during the loading process.
- During loading, Explorer stops processing user updates to give priority to
  geometry/texture loading. As a result, those removal intentions triggered by Pulse
  are enqueued and not processed at that time.
- When the user goes back to Genesis Plaza, those pending messages are finally
  processed, causing the other (remote) users to be removed from the scene.

## Impact

- **Severity**: SEV-2
- **Users affected**: Platform-wide, affecting users intermittently.
- **Symptom**: Traveling to Genesis Plaza from a World could cause remote users to disappear from the scene until it is reloaded.
- **Duration**: Crash opened July 7 at 21:50 UTC (and again July 7 at 22:52 UTC). Reopened July 8 at 06:22 UTC and initially misattributed to a World exceeding the storage limits. Fix deployed as a hotfix on July 10 (v.0156.0).
- **Trigger**: Teleporting back to Genesis Plaza from a World, following the deployment of [unity-explorer#9041](https://github.com/decentraland/unity-explorer/pull/9041).

## Solution

[unity-explorer#9041](https://github.com/decentraland/unity-explorer/pull/9041) was
reverted. [unity-explorer#9338](https://github.com/decentraland/unity-explorer/pull/9338)
will solve the separate (but related) ghost avatars issue by making Pulse
announcements realm-dependent.

A small mitigation was deployed as a hotfix
([commit 6aab805](https://github.com/decentraland/unity-explorer/commit/6aab8055e616bc662d619f7c104141d75de230f9)):
a rejoin from a user empties any pending removal intention, so the enqueued removals no
longer fire when returning to Genesis Plaza.

## Preventive Actions

- **Guard against pending removal intentions on rejoin**: The mitigation fix also acts as a guard for related issues in the future. By removing the enqueued removal intentions of a rejoined user, we prevent similar scenarios where pending Pulse removals are processed late and drop remote users from a scene.
