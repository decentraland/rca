# September 2, 2026 - A stored javascript: forum link in Builder ran in a curator's session

|                          |                   |
| -----------------------: | :---------------- |
|             **Reported** | August-31-2026    |
|           **Mitigation** | September-02-2026 |
|   **Solution Completed** | September-02-2026 |

## Description

- A collection's `forum_link` points to its Discourse thread and is meant to be written by builder-server when the collection is published. The client's save payload also carried the field, and the server schema accepted any string, so an ordinary creator could store `javascript:` code in it.
- The curation page that committee members use renders a **Link** control that opened that value with `window.open`. Clicking it ran the stored code in the Builder origin, with access to `localStorage`, where the curator's delegated signing identity lives for 31 days.
- With that identity the attacker can sign Builder API requests as the committee member until it expires, including `PATCH /v1/collections/:id/curation`, which assigns reviews and sets a collection to approved or rejected. The victim is necessarily a committee member and has to click the link control; the identity does not sign blockchain transactions.

### Root cause

A field only the server should write was accepted from the client without a scheme check, and the value was rendered into a navigation sink that treats any string as a URL. Validation at save time checked shape, and the render trusted whatever was stored.

## Severity

Websites & Applications - High.

This matched "theft of an active user authentication credential". It reached a privileged flow but needed a click from a committee member and gave no on-chain access.

## Solution

Both sides changed on September 2.

- [builder-server](https://github.com/decentraland/builder-server/commit/72b3356) ignores server-managed fields such as `forum_link`, `reviewed_at`, `is_published` and `is_approved` in collection and item writes, and `forum_link` must match an `https` URL of at most 512 characters.
- [builder](https://github.com/decentraland/builder/commit/87a8d28) routes external links through a helper that accepts only `https` URLs without embedded credentials and opens them with `noopener,noreferrer`. The forum link on the collection detail page, the curation row, the rejection modal and the publish modals use it, the client no longer sends `forum_link` or `reviewed_at` when saving, and the value read from the API is sanitized before it is stored in the client state.
