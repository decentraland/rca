# September 2, 2026 - The Auth request page previewed one typed-data payload while the wallet signed another

|                          |                   |
| -----------------------: | :---------------- |
|             **Reported** | August-31-2026    |
|           **Mitigation** | September-02-2026 |
|   **Solution Completed** | September-02-2026 |

## Description

- This is the signing branch of the request page covered in [2026-08-27](2026-08-27.md). For `eth_signTypedData_v4` the page chose what to show by taking the first param that was a JSON string and not an address, and ran its approval warning on that payload. The dispatch forwarded the params array unchanged, and the Thirdweb adapter used for email and social wallets signs `params[1]`.
- A request shaped `[benign Statement, EIP-2612 Permit]` therefore showed the Statement with no warning, and **Allow** produced a valid signature over the Permit. The attacker could spend that approval and move the victim's token balance.
- The preconditions were the same as in August: a Thirdweb wallet, and the victim opening a request created by the attacker's page and approving within 300 seconds. Auth 5.0.3 had fixed only the `eth_sendTransaction` branch.

### Root cause

The reviewed and the dispatched payload disagreed again, in the branch the August fix did not cover. The page searched the params for something to display instead of requiring a single canonical shape.

## Severity

Websites & Applications - Critical.

Same category and calibration as [2026-08-27](2026-08-27.md): it depends on the victim approving a request reached from outside our UIs, and only email and social wallets are exposed.

## Solution

[Auth 5.0.4](https://github.com/decentraland/auth/pull/463) (September 2) accepts signature requests only in their canonical shape: `personal_sign` as `[message, signer]`, and typed data as `[signer address, exactly one typed JSON payload]`. Anything else is rejected before the page renders and cannot be retried. The v1 `eth_signTypedData` method, which no client uses, was removed from the allowed methods.

A [follow-up](https://github.com/decentraland/auth/pull/464) (September 3) makes a request rejected at that point report a failed outcome to the client that sent it, instead of leaving it waiting until the request expires.
